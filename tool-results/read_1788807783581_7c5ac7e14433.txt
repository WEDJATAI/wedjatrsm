    24→## Order money model
    25→
    26→- subtotal = Σ(item.quantity × unitPrice)
    27→- discount (absolute EGP, 0 ≤ discount ≤ subtotal)
    28→- tax = (subtotal − discount) × TAX_RATE
    29→- total = subtotal − discount + tax
    30→- paidAmount = Σ payments; remaining = total − paidAmount
    31→- Order auto-closes (status='paid', closedAt, inventory deducted, table freed) when paidAmount ≥ total − 0.02.

    33→## API contracts (response shapes are BINDING)
    34→
    35→All endpoints return JSON; errors: `{ "error": string }` with 4xx/5xx. Auth via httpOnly cookie (login sets it). Role gates noted per endpoint.
    36→
    37→### Auth
    38→- `POST /api/auth/login` body `{ email?, password?, pin? }` (pin OR email+password) → `{ user: SessionUser }` + sets cookie. 401 on bad creds.
    39→- `POST /api/auth/logout` → `{ ok: true }`
    40→- `GET /api/auth/me` → `{ user: SessionUser }` or 401.
    41→
    42→### Users (admin)
    43→- `GET /api/users` → `{ users: (SessionUser & {active:boolean; pin:string|null; createdAt:string})[] }` (no passwordHash)
    44→- `POST /api/users` `{ name,email,password,role,pin? }` → `{ user }`
    45→- `PUT /api/users/[id]` `{ name?,role?,pin?,active?,password? }` → `{ user }`
    46→
    47→### Categories (read: any authed; write: admin)
    48→- `GET /api/categories?all=1` → `{ categories: Category[] }` (default active only; `all=1` includes inactive; each has productCount)
    49→- `POST /api/categories` `{ name, displayOrder? }` → `{ category }`
    50→- `PUT /api/categories/[id]` `{ name?, displayOrder?, active? }` → `{ category }`
    51→- `DELETE /api/categories/[id]` → soft delete (active=false) `{ ok:true }`
    52→
    53→### Products (read: any authed; write: admin)
    54→- `GET /api/products?category=<id>&all=1&sellable=1&stockable=1&search=<q>` → `{ products: Product[] }` (includes `category:{id,name}|null`; default: active only)
    55→- `POST /api/products` `{ name, categoryId?, price, cost, isStockable?, isSellable?, sku?, imageUrl?, lowStockThreshold?, stock? }` → `{ product }` (initial stock ⇒ 'purchase' inventory transaction if stockable)
    56→- `PUT /api/products/[id]` same fields (stock only via inventory adjust; price/cost updates allowed) → `{ product }`
    57→- `DELETE /api/products/[id]` soft delete → `{ ok:true }`
    58→
    59→### Floor plans & tables
    60→- `GET /api/floorplans` → `{ floorPlans: FloorPlan[] }` (each with tables incl. polling extras: openOrderId, openOrderTotal, openOrderItemCount, openOrderSince)
    61→- `POST /api/floorplans` `{ name }` (admin) → `{ floorPlan }`
    62→- `PUT /api/floorplans/[id]` `{ name?, active? }` (admin) → `{ floorPlan }`
    63→- `POST /api/tables` (admin) `{ floorPlanId, name, capacity?, positionX?, positionY? }` → `{ table }`
    64→- `PUT /api/tables/[id]` `{ name?, capacity?, positionX?, positionY?, status?(free|reserved only), active? }` (admin) → `{ table }`
    65→- `GET /api/tables/status` (any authed) → `{ tables: RestaurantTable[] }` with polling extras — optimized for POS polling (3s)
    66→
    67→### Orders (waiter/admin)
    68→- `POST /api/orders` `{ tableId?: number|null, items: [{productId, quantity, notes?, course?}] }` → `{ order: Order }` (validates stock; sets table occupied; items status='new')
    69→- `GET /api/orders?status=open` → `{ orders: Order[] }` (with items, payments, table, paidAmount, remainingAmount; sorted createdAt asc)
    70→- `GET /api/orders/[id]` → `{ order: Order }`
    71→- `PUT /api/orders/[id]` `{ addItems?: [{productId,quantity,notes?,course?}], removeItemIds?: number[], updateItems?: [{id,quantity,notes?,course?}], discountAmount?: number }` → `{ order }` (recompute totals; stock validation on addItems; removed items deleted)
    72→- `POST /api/orders/[id]/payments` (waiter/admin) `{ payments: [{method, amount, reference?}] }` → `{ order, paidAmount, remaining, closed:boolean }` — rejects overpay (sum > remaining + 0.02 → 400). If fully paid → auto close (status paid + closedAt + inventory deduction + table freed) and `closed:true`.
    73→- `POST /api/orders/[id]/close` (waiter/admin) → only succeeds if remaining ≤ 0.02 → `{ order, closed:true }`; else 400.
    74→- `POST /api/orders/[id]/cancel` (admin or creating waiter) → `{ order }` (status cancelled, table freed, NO inventory deduction)
    75→- `PUT /api/order-items/[id]` (kitchen/waiter/admin) `{ status?: 'new'|'preparing'|'ready'|'served', notes?, quantity? }` → `{ item }`
    76→
    77→### Inventory (read: waiter/admin; adjust: admin)
    78→- `GET /api/inventory` → `{ items: InventoryItem[] }` (stockable products: stock, cost, value=cost×stock, isLow)
    79→- `GET /api/inventory/low-stock` → `{ items: InventoryItem[] }`
    80→- `GET /api/inventory/transactions?limit=100` → `{ transactions: InventoryTransaction[] }` (with product name, desc by date)
    81→- `POST /api/inventory/adjust` (admin) `{ productId, quantityChange (±), reason('purchase'|'adjustment'|'waste'), note? }` → `{ product }` (reject stock < 0; updates product.stock + transaction)
    82→
    83→### Recipes (admin)
    84→- `GET /api/recipes?productId=<id>` → `{ components: RecipeComponent[] }` (with ingredient info) — NOTE: productId is a QUERY PARAM (path segment conflict with DELETE [id])
    85→- `POST /api/recipes` `{ productId, ingredientId, quantity }` → upsert on (productId,ingredientId) → `{ component }`
    86→- `DELETE /api/recipes/[id]` (id = componentId) → `{ ok: true }`
    87→
    88→### Reports (admin)
    89→- `GET /api/reports/sales?from=YYYY-MM-DD&to=YYYY-MM-DD` (inclusive; to end-of-day) → `SalesReport`: `{ totalRevenue, totalOrders, avgOrderValue, byMethod[], topProducts[](top 8), byCategory[], byDay[], byHour[] }` (paid orders only; revenue = Σ totalAmount; from defaults to 30 days ago, to defaults to today)
    90→- `GET /api/reports/inventory-value` → `{ totalValue, itemCount, lowStockCount }`
